## 2. 採用的做法

- 讀 `/api/behaviors`（開頁一個請求）與 `/api/behaviors/detail`（點一段行為才打，打過的記住不再打）。不在瀏覽器裡切段，也不在瀏覽器裡判斷分級。
- 約定 v0.1 的五點都已照做：
  - 用伺服器的 `actor.id`。
  - 「直連 apiserver」標籤只看 `direct`；`bypassed_rancher` 只列在「觸發的規則」，標明只當標籤。
  - 紅點畫在 `summary.look[]` 的位置。
  - 伺服器不接受 `from`／`to`，所以時間範圍由介面自己處理：只留下和範圍重疊的段落，不重新切段、不改件數，並寫明「上面的件數仍是整天」。
  - `ace` 寫成「直連下游叢集的授權端點」。
- 介面自己的語言選單：跟隨 Rancher／中文／English，存在這個瀏覽器，不動 Rancher 帳號的語言設定。截圖的中英切換用的就是它。
- 亮暗主題跟 Rancher 走。截圖時只在這個分頁切換 `body` 的主題 class，沒有改帳號設定。
- 開發載入：用 `python3 -m http.server 4611` 提供 `dist-pkg`，在分頁裡 `removePlugin` 後再 `loadAsync('audit-loupe-0.7.0', …)`。只影響這個分頁，沒有用 helm，也沒動叢集上的 0.6.0。

## 6. 本任務書哪裡害我走冤枉路

1. **「未記錄執行者」的鍵**：任務書和約定 v0 都說 `actor.key` 為空字串，但又要每座叢集一列。我先自己組「`~`＋叢集」，約定 v0.1 才給 `id`。一開始就寫進 v0 就不用改兩次。
2. **時間範圍**：任務書第 4 節說「底部時間列沿用 v5」，但沒提 v5 時間列會篩選整頁、需要後端支援 `from`／`to`。第一階段先拿掉範圍篩選，v0.1 回答後才改成介面自己留下重疊的段落。
3. **中英切換與亮暗主題**：第 7.4 節要中／英、亮／暗截圖，但 Rancher 的語言與主題都是帳號設定、不能動。要先問清楚，才知道需要介面自己的語言選單。
4. **12 格**：四分頁 × 亮／暗 × 中／英 是 16 格，任務書寫 12 格。我照 16 格的表排，拍了 13 格。
