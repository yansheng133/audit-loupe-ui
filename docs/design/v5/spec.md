## 1. 版面

由上到下、左到右：

1. **分頁列**（高 44px）：左邊「總覽／關係／事件」三個分頁；右邊篩選（叢集、Namespace、稽核狀態），最右邊時區。切換分頁時篩選保留。
2. **主區**：目前分頁的內容。
3. **右側物件細節**（寬 400px）：選了物件才出現；開頁時預設選排序第一的物件。可以關閉。
4. **底部時間列**（固定，三個分頁都有）。

- 窄螢幕（主區寬度不夠放表格＋細節）：細節改成覆蓋在主區上的抽屜。
- 沿用現有的側邊選單收合與全螢幕（`html.al-nav-collapsed`、`.al-full`，見 `ChangeMap.vue` 與 `change-map.scss`）。
- 顏色用 Rancher 主題變數，亮色、暗色都要能看；狀態色對照設計稿的 `--bad`、`--dim`、`--ok`、`--und`。

## 2. 稽核狀態（四種，全頁一致）

| 狀態 | 標籤 | 樣式 | 判斷（依 `layer1-plan.md` 第 1 節，後端算好） |
|---|---|---|---|
| 要看 | 要看・高／要看・中 | 紅色實心淡底 | 當天有中、高風險警示 |
| 看不清 | 看不清 | 橘色實心淡底 | 有變化但找不到執行者（事後比對，或該叢集沒收 apiserver audit） |
| 看不到 | 看不到 | 灰色虛線框、斜線底 | 落在「沒有收集」的缺口邊緣 |
| 清楚 | 清楚 | 綠色外框、無底色 | 以上都不是；低風險只當淡色提示 |

- 每個標籤滑鼠移上去，都要說明判斷依據（規則代碼、缺口原因等）。

## 3. 總覽分頁

- **上方一行**：「N 個物件有變更 ・ M 筆操作（不含系統元件）」，後面接四種狀態的件數標籤。標籤可以點，點了就套用狀態篩選。
  - 載入中顯示「—」，不顯示 0（原則 1）。
- **表格欄位**：稽核狀態｜物件（種類標籤＋名稱）｜叢集／Namespace｜當天操作（00–24 的迷你條，紅色是有警示的那幾筆）｜次數｜最後一次｜誰（附身分分類小標）｜管道。
- **排序**：依狀態（要看→看不清→看不到→清楚），再依最後一次時間新到舊，與 API 相同。翻頁或捲動載入用 API 的 `cursor`；列數多時只畫看得到的列。
- **表格最下面一行**：說明有幾列被隱藏（系統元件、Rancher 介面自己的維護動作），附「顯示」切換。
- **點一列**：右側細節換成那個物件，網址同步更新（見第 8 節）。

## 4. 關係分頁

- **由左到右四欄**：身分 → 管道 → 叢集 → 物件。
- **物件節點**依稽核狀態上色；**線的粗細**代表次數；**繞過 Rancher**（直連 apiserver）的線畫成紅色虛線。
- **身分超過上限**（API 決定）時合併成群組，例如「叢集元件 12 個」，點了可以展開。
- **選取的物件**：從身分到物件整條路徑亮起來，其他線變淡。
- **點節點就篩選**：點身分只看它碰過的物件，點管道、叢集同理。目前套用中的篩選要顯示，並能一鍵清除。

## 5. 事件分頁

- **只列稽核狀態的轉變**，不列每一筆操作。例如：
  - 「物件 X：要看・中 → 要看・高（規則重新計算）」
  - 「rke2 收集：正常 → 看不到」
- **收集的事件有兩種來源，都要列出，用標籤分開**（需求第 4 節第 8 點：自己的失敗也要顯示）：
  - **收集元件回報**：例如重新啟動、檔案遺失、檔案被換掉、狀態遺失，附原因與精確起訖。
  - **Audit Loupe 自己沒收到心跳**：寫成「Audit Loupe 的收集元件沒有回報」，不能被前一種蓋掉。
- 被擱置的行：在收集事件裡顯示筆數，點了連到收集狀態頁的清單（只顯示時間、檔名與位置、原因、sha256，不顯示原文）。

## 6. 底部時間列

- **預設**：一條合併線，代表所有叢集；每格取當時最嚴重的狀態。每 10 分鐘一格。
- **在上方篩選選了叢集之後**：選了幾個叢集就分成幾條線。只選一個叢集時改成每分鐘一格（資料來自後端的每分鐘彙總表，不在瀏覽器計算）。
- **線的畫法**：
  - 看不到：斜線空白，不畫成 0。
  - 要看：紅色。
  - 狀態還無法判斷：灰色。
  - 有操作的時間點：在線上畫細短線。
- **日期**：左邊有前一天／後一天和日期選單。
- **選取時間範圍**：點一格選那一格，拖曳選一段（對齊整格）；整頁只算這段時間，時間列保持整天，範圍外變暗。
  - **不做播放頭**（Sam 10/21 決定：能選範圍、呈現範圍內的內容就好）。
- **圖例**放在時間列右上方。

## 7. 右側物件細節

由上到下：

1. **標題區**：種類標籤、名稱、叢集／Namespace、稽核狀態標籤，以及一句白話的原因（例如「有人進入容器」）。
2. **當天的稽核狀態條**：00–24，在出現警示的時間點標記。
3. **三個動作**：
   - 看最後一次變更：前後版本差異。
   - 看目前狀態：最新一份物件內容。
   - 看設定差異：可以選任兩個版本比較。
   - 沒有物件版本的資源（例如 Node），按鈕要停用，並說明原因：「這類資源沒有收物件版本」。
4. **誰動了它**：時間、身分（附分類小標與一句身分說明，例如「本機帳號，可能多人共用」「憑證身分，對不到個人」）、動作、管道。原始的 verb、resource、身分字串放在展開或滑鼠移上去時顯示（原則 6）。
5. **取決於設定的小標**：這筆紀錄有因為設定而看不到的部分時才出現。例如進入容器時：「取決於設定：是否啟用 SUSE Security 收集」。
6. **底部**：
   - 匯出：JSON，含原始紀錄、判斷時的規則設定代碼、雜湊與驗證結果。
   - 複製連結。
   - 雜湊鏈狀態：驗證通過／斷開／尚未驗證。

## 8. 網址與分享

網址要能還原整個畫面：日期、篩選、分頁、選取的物件、時間範圍。複製連結就是複製目前的網址。

## 9. 文字

- 白話在前，Kubernetes 原文可以展開來看。
- 用台灣用語。中文、英文兩套都要（沿用 `lib/model.js` 現有的語系機制）。
- 時區與上班時間是設定值，滑鼠移上去要顯示設定值與來源。

## 10. 5 秒與載入

- 開頁只送 `/api/changemap` 一個請求（`layer1-plan.md` 第 4 節）。在路由進入時送出、不等元件掛上；不等 Rancher 的叢集與專案清單，名稱晚到就先顯示 ID（需求第 3.4 節）。
- 切換分頁、篩選、翻頁：只送使用者實際操作對應的請求，不預讀（需求第 3.4 節 (4)）。
- 處理中（重新計算、收集元件重新啟動等）：在分頁列下方顯示進度列（需求第 3.7 節）。

## 11. 驗收

1. 三個分頁、右側細節、時間列都和設計稿截圖的結構一致；資料全部來自 API。
2. 用 lab 實際資料開頁：
   - 開頁只有一個 API 請求（看瀏覽器網路紀錄）。
   - 載入中沒有出現 0。
   - 畫面上沒有 ‹待確認›。
3. 選一個叢集時，時間列變成每分鐘一格，而且不在瀏覽器裡重算。
4. 收集事件兩種來源都看得到（可用 lab 實測輪替時留下的缺口，或回放測試產生的缺口）。
5. 複製連結開到新分頁，看到同一個畫面。
6. 亮色、暗色主題，中文、英文都走一遍。
7. 舊頁面（權限覆核、收集狀態、規則）不受影響。
